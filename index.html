03 / Engineering notes

The thinking behind the work.

Short technical notes. Over time, these can grow into public posts and runnable GitHub examples.

DATA RELIABILITY / 4 MIN READ

A sync job should be safe to run twice.

Retries are unavoidable. Duplicate processing should not be.

Read note

I prefer separating detection of changes from application of changes. Each batch should have an identifiable set of records, and processing should be able to recognize what has already succeeded. Failures need to leave enough state for a clean retry. Idempotence is a design decision, not a final error-handling patch.

SQL SERVER / 3 MIN READ

Before rewriting a slow query, find the real cost.

Start with execution evidence rather than guessing at indexes.

Read note

Check how often the query runs, what rows it actually reads, whether estimates differ from reality, and if blocking is part of the delay. An index can help, but it can also increase write cost. I look for the smallest change that fixes a measured bottleneck and can be tested safely.

JOB DESIGN / 3 MIN READ

A schedule is not a concurrency strategy.

Two jobs can overlap even when their start times don't.

Read note

Execution time varies. If overlapping runs can corrupt status or process the same records, clock-based spacing isn't enough. I prefer explicit coordination, clear batch ownership, and monitoring that shows when a run was skipped, delayed, or failed.
